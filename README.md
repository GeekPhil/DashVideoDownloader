# DASH 协议视频下载器

把 bilibili 和 YouTube 上的学习视频下载到本地，供没有网络的设备反复观看。

一个面向个人使用的 Windows 桌面下载器 —— 单个 Python 文件承载全部逻辑，以 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 为下载引擎，自建界面、任务队列与风控策略。目标是「够用就好」：不内置浏览器、不做转码、不做多站点适配层，把复杂度留给引擎。

## 功能

**下载与格式**

- 支持 bilibili、YouTube，含 `b23.tv` / `youtu.be` 短链
- 自动取视频标题作文件名；合集/分 P 使用**分 P 自己的标题**，而非合集名
- 清晰度下拉选择，**默认选中「有 H.264 可选的最高清晰度」**
- 同一清晰度下可选 H.264 / HEVC / AV1 / VP9，每个选项标注预估体积
- 音频质量可选：最高 / 192k / 128k / 64k
- 字幕以**同名 `.srt` 文件**旁挂下载，不烧录进画面

**任务管理**

- 多任务队列，并发数 1~3 可调；任务列表倒序，新任务在最前
- 每个任务独立显示进度条、速度、已下载体积与用时
- 排队中 / 下载中可随时取消，取消会一并清理临时文件
- 失败任务可原地重试，沿用原先选定的清晰度，无需重新解析
- 分 P / 合集弹出勾选列表，**默认全不勾**，防止手滑拉下一整个合集

**安全与稳健**

- 登录凭据**永不直接交给 yt-dlp**：只传一份用完即删的临时副本
- 启动时自动清理上次异常退出遗留的凭据副本
- 启用登录态时并发强制降为 1，并在请求之间插入随机停顿
- 命中限流（429 / 412）时全局冷却 60 秒，而不是继续重试
- bilibili 走直连、其余站点自动复用系统代理
- 启动即自检 ffmpeg / yt-dlp / JS 运行时 / 代理，缺什么在状态栏直说

## 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 | 程序用 `winreg` 与 `ctypes` 读取系统代理、开启高 DPI，**仅支持 Windows** |
| Python | 3.10 或更高 | 下限由 yt-dlp 决定 |
| ffmpeg | 较新版本，且位于 `PATH` | DASH 音视频分轨必须由它合并，**缺失则完全无法下载** |
| JS 运行时 | Node.js / Deno / Bun / QuickJS 任一 | YouTube 的签名挑战需要，**缺失则 YouTube 不可用**；bilibili 不需要 |

Python 依赖见 `requirements.txt`：`customtkinter`、`yt-dlp`、`yt-dlp-ejs`。

## 安装

```bash
git clone https://github.com/GeekPhil/DashVideoDownloader.git
cd DashVideoDownloader
python -m pip install -r requirements.txt
```

补齐 ffmpeg 与 JS 运行时（以 winget 为例）：

```powershell
winget install Gyan.FFmpeg
winget install OpenJS.NodeJS
```

装完请**新开一个终端**让 `PATH` 生效，随后用 `ffmpeg -version` 和 `node -v` 确认能调用到。

## 运行

```bash
python main.py
```

不想看到控制台黑窗，改用 `pythonw`：

```bash
pythonw main.py
```

程序会在自身所在目录生成两个文件，都可随时删除：

- **`config.json`** —— 保存目录、并发数、登录态等设置，退出时自动写入。删掉即恢复默认。
- **`启动日志.txt`** —— **仅在启动失败时生成**，内含完整报错堆栈。

## 使用

1. 粘贴链接 → 按回车（或点「解析」）
2. 等待解析完成，任务卡片出现
3. 在卡片上选择清晰度与字幕
4. 点「开始下载」

可连续添加多个任务，程序会自动排队。

### 清晰度怎么选

卡片上的下拉菜单大致长这样：

```
1080P · H.264 · 71.7 MB     ← 默认选这个
1080P · HEVC · 19 MB        ← 体积仅 1/4，但老旧设备可能放不了
1080P · AV1 · 15 MB         ← 体积最小，兼容性最差
720P · H.264 · 49.5 MB
```

**默认选中「有 H.264 可选的最高清晰度」**，因为 H.264 兼容性最好，几乎所有设备都能播。若确认播放设备支持、想省空间，可手动改选 HEVC 或 AV1 —— 改选后卡片上会出现一行橙色提示。

体积段是视频轨与音频轨之和的预估值；取不到体积时该段直接省略。高帧率（≥ 50fps）会额外标注 `60fps`，2160P 及以上显示为 `4K`。

若该链接没有任何带视频流的格式（例如纯音频内容），下拉菜单里会出现一条「仅音频」选项。

### 字幕

选择结果会存成与视频同名的 `.srt`，放在同一目录：

```
课程介绍.mp4
课程介绍.zh-CN.srt
```

播放器（PotPlayer、VLC 等）会自动加载。字幕**不烧录进画面**，可随时开关、切换语言，也不影响画质。

三个选项的含义：

| 选项 | 行为 |
| --- | --- |
| 不下字幕 | 只下视频 |
| 中文（人工 + AI） | 下载中文的官方字幕与自动字幕 |
| 全部语言 | 展开为该视频**实际存在的主要语言**，而非字面意义的全部 |

> 「全部语言」不下载 YouTube 那上百种机翻字幕 —— 那些内容几乎没有价值，还会把目录塞满。

### 分 P / 合集

粘贴分 P 视频（合集）的链接，会弹出勾选列表：

- **默认全不勾**
- 若链接带有 `?p=3`，则默认只勾第 3 集
- 勾选 2 集以上时，自动建立以合集名命名的子文件夹

### YouTube 必须配置登录态

不配置的话 YouTube **完全下不了**（会提示要求登录验证）。这是 YouTube 的反爬机制，与网络环境无关。

1. 在 Chrome 安装扩展 **Get cookies.txt LOCALLY**（开源，纯本地处理，不上传任何数据）
2. 打开 YouTube，**确认已登录**
3. 点扩展图标 → **Export**，保存为 `cookies.txt`
4. 在本软件中打开「登录态」开关，在文件框中选中该 `txt`

> ⚠️ 该文件**等同于你的账号密码**。只应留在本地，不要上传网盘、不要发给他人。

导出后看窗口底部状态栏即可确认是否有效：

- `登录态 cookies.txt` → ✅ 有效
- `⚠ 登录态文件不含登录凭据，YouTube 会失败（请重新导出）` → ❌ 无效，请重导

无效的常见原因是导出时浏览器其实处于**未登录状态**（登录已过期），或从错误的站点页面导出。导出前请先在浏览器打开 YouTube，确认右上角是你的头像。

> 为什么不直接读浏览器的 cookie？Chrome 127 起启用 App-Bound 加密，第三方程序无法解密其 cookie 数据库（这是 Chrome 的刻意设计）。本程序**不绕过**该机制。

### bilibili 需要登录态吗

**不需要**，免登录即可下载 1080P。

## 设计说明

### 不转码，只封装

程序只做容器封装，不做转码：视频原本是什么编码，存下来就是什么编码。

- **好处**：速度快（合并通常几秒），画质零损失。
- **代价**：选了 HEVC / AV1 时，拷到老旧设备上可能打不开。

若某条轨道与 mp4 容器不兼容（例如 YouTube 的 Opus 音频），会自动改用 `.mkv` 而**不是**转码。

### 为什么启用登录态就变成单线程

这是刻意为之，为了账号安全。用同一套凭据向 bilibili 并发发起请求，是最典型的脚本行为特征；串行虽慢，但在风控视角下更接近真人。除强制并发数为 1 外，还额外做了：

- 每个网络请求之间强制间隔 1 秒
- 分片下载之间插入随机停顿（0.5~1.5 秒），避免机械的等距节奏
- 命中限流（429 / 412）时**全局暂停 60 秒**，而不是立刻重试
- 失败不会疯狂自动重试

### 登录凭据的处理

程序**不直接**把用户的 `cookies.txt` 交给 yt-dlp，而是复制一份到系统临时目录再传路径：

- 临时副本在程序退出时删除；
- 若上次是强杀或断电导致没删成，下次启动时自动清理（只清理自己命名的、且超过 24 小时未变动的文件，避免误删仍在运行的实例）；
- 复制过程若中途失败，也会立刻清掉半成品，不留残留。

### 文件名与重名

- 非法字符（`\ / : * ? " < > |`、控制字符，以及 yt-dlp 模板里的转义符 `%`）会被**移除**，而非替换成下划线
- 标题若自带媒体扩展名（如 `讲义.mp4`）会先剥掉，避免存成 `讲义.mp4.mp4`
- 结尾的句点与空格会被去掉；Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`~`COM9`、`LPT1`~`LPT9`）会自动加前缀避开
- 过长文件名截断至 150 字符
- 标题全为空白时回退为 `Dash_日期时间`
- 目标文件已存在时，自动追加 ` (1)`、` (2)` 递增，绝不覆盖既有文件

## 常见问题

| 现象 | 原因与解决 |
| --- | --- |
| 运行后没反应 / 窗口一闪而过 | 查看程序目录下的 `启动日志.txt`。有该文件 = 启动失败，日志里有完整原因；没有 = 启动成功，问题在别处 |
| 完全无反应且无日志 | 在命令行手动跑一次 `python main.py` 看报错 |
| 状态栏显示「未找到 ffmpeg」 | ffmpeg 不在 `PATH` 中，检查环境变量后新开终端 |
| 状态栏显示「未检测到 JS 运行时」 | 装 Node.js（或 Deno / Bun / QuickJS）后重启程序 |
| YouTube 提示要求登录验证 | 看状态栏的登录态提示，多半是导出的 cookie 不含真正登录凭据，重新导出 |
| 提示需要登录但已开登录态 | `cookies.txt` 已过期，重新导出 |
| bilibili 变慢或失败 | 可能触发限流，程序会自动冷却 60 秒，稍候再试 |
| 所有站点都下不了 | 检查网络。YouTube 需要代理（程序自动复用系统代理），bilibili 走直连 |
| 网站改版导致下载失效 | 升级引擎即可，通常无需改代码：`python -m pip install -U yt-dlp yt-dlp-ejs` |
